# Система сверки БУ ↔ ПУ (НПФ)

Автоматическая сверка **бухгалтерского учёта (БУ)** и **персонифицированного
учёта (ПУ)** негосударственного пенсионного фонда.

Система забирает входные файлы (Excel и JSON) из двух каталогов, распознаёт их
тип и структуру, извлекает нужные данные, приводит даты и суммы к единому виду,
считает суммы **по дням и за период**, сверяет БУ с ПУ по каждому показателю,
находит расхождения с указанием дат и формирует:

- **итоговый Excel-отчёт** (лист «Свод» + лист «Детализация»);
- **обезличенное саммари** (`JSON`) и **готовый промт** для внешней LLM —
  чтобы во внутреннем контуре получить краткое текстовое описание результатов
  (без передачи персональных данных).

## 📁 Что куда класть (работа с реальными данными)

Положите файлы в каталоги (создаются автоматически при первом запуске):

```
data/ПУ/                                  data/БУ/
├── Выплата (пенсия, ВС, НС).xlsx         ├── 397.03 Страховой резерв <период>.xlsx
├── Пенсионные взносы ФЛ.xlsx             └── НПО_<период>.json
├── Пенсионные взносы ЮЛ.xlsx
├── Целевые взносы ФЛ.xlsx
├── Целевые взносы ЮЛ.xlsx
└── Страховой резерв.xlsx
```

Имена распознаются **по подстроке без учёта регистра** — точный суффикс с
датой/периодом не важен. Лишние, временные (`~$…`) и неподдерживаемые файлы
игнорируются автоматически.

Затем:

```bash
python -m npf_recon          # сверка по вашим файлам
```

Результаты появятся в `output/`:

| Файл | Назначение |
|---|---|
| `Сверка_БУ_ПУ.xlsx` | Итоговый отчёт: «Свод» + «Детализация» |
| `Саммари_БУ_ПУ.json` | Обезличенные итоги для LLM (без персональных данных) |
| `Промт_для_LLM.txt` | Готовый промт (инструкция + JSON) для внешней LLM |

```bash
python -m npf_recon -v                    # подробный лог

```

## 📊 Как читать итоговый отчёт

**Лист «Свод»** — строка на каждый из 14 показателей:

| Виды движений | БУ Сумма | БУ Дата | ПУ Сумма | ПУ Дата | Расхожд. Сумма | Расхожд. Дата |
|---|---|---|---|---|---|---|
| Страховой резерв | 406 500,00 | 01.02–28.02 | 391 500,00 | 01.02–28.02 | **15 000,00** | **17.02.2026** |
| Целевые взносы ЮЛ | 363 500,00 | … | 363 500,00 | … | _(пусто)_ | **10.02.2026, 24.02.2026** |

- **Расхождение по итогу** — когда месячные суммы БУ и ПУ различаются.
- **Расхождение только по дням** — когда месячные итоги совпали, но отдельные
  дни различаются (взаимно компенсирующиеся отклонения). Такие даты тоже
  попадают в отчёт и подсвечиваются.

**Лист «Детализация»** — по каждой дате расхождения: показатель, дата,
сумма БУ, сумма ПУ, разница.

## 🤖 Передача результатов внешней LLM (обезличенно)

Текстовое саммари отчёта генерируется **во внутреннем контуре на отдельном
сервере**. Эта система готовит для него вход — **без персональных данных**:

- `output/Саммари_БУ_ПУ.json` — только агрегаты: показатели (категории),
  даты, суммы, факт/тип/сумма расхождений. **Нет** ФИО, договоров, счетов и
  имён файлов (модель данных `Record` их в принципе не хранит).
- `output/Промт_для_LLM.txt` — системная инструкция на русском + этот JSON;
  файл можно целиком отправить в LLM, которая вернёт краткое деловое описание.

Программно:

```python
from npf_recon.llm_export import build_summary, build_prompt
summary = build_summary(recon_rows, "Февраль 2026")   # dict без перс. данных
prompt  = build_prompt(summary)                        # готовая строка-промт
```

## 🧩 Реестр файлов → показатели

### Папка ПУ

| Подстрока в имени | Показатель | Формат | Дата | Сумма |
|---|---|---|---|---|
| `Выплата` | по `ВидВыплат` → 3 показателя | Excel с заголовком | «Дата операции» | «Сумма» |
| `Пенсионные взносы ФЛ` | Пенсионные взносы ФЛ | Excel | A | H |
| `Пенсионные взносы ЮЛ` | Пенсионные взносы ЮЛ | Excel | A | H |
| `Целевые взносы ФЛ` | Целевые взносы ФЛ | Excel | A | H |
| `Целевые взносы ЮЛ` | Целевые взносы ЮЛ | Excel | A | C |
| `Страховой резерв` | Страховой резерв | Excel | A | I |

`ВидВыплат`: «Негосударственная пенсия» → **Выплата пенсии**;
«Выкупная сумма (Расторжение)» → **Выплата выкупных сумм**;
«Выкупная сумма (Наследникам)» → **Выплата наследуемых сумм**.

### Папка БУ

| Подстрока в имени | Показатель | Формат |
|---|---|---|
| `397.03 Страховой резерв` | Страховой резерв | Excel (A=дата, I=сумма) |
| `НПО` | 4 показателя взносов | JSON (`components[].name`) |

Маппинг компонентов JSON: «… по договорам НПО» → соответствующий взнос;
«Целевые взносы ФЛ/ЮЛ» → одноимённые показатели.

Всё сопоставление файлов и показателей — в одном месте:
[`config/mappings.py`](config/mappings.py). Колонки можно задавать индексом
(`7`) или буквой Excel (`"H"`).

## 🔢 Что система понимает в данных

**Даты:** `DD.MM.YYYY`, `DD.MM.YY`, `YYYY-MM-DD`, ISO с временем
(`2026-02-01T00:00:00`), Excel datetime.

**Суммы:** `1234.56`, `1 234,56` (обычный/неразрывный/узкий пробел),
американская группировка `100,000.00`, бухгалтерские скобки `(1 234,56)`,
завершающий минус `1 234,56-`, Unicode-минус `−`, валюты `₽ / руб. / RUB`,
прочерк `–` как пустое значение.

Несколько операций за один день суммируются; «мусорные» строки (заголовки,
подытоги, пустые суммы) пропускаются.

## ⚙️ Настройка путей (продуктив)

По умолчанию данные читаются из `data/ПУ` и `data/БУ`. Для продуктивной среды:

| Переменная окружения | Назначение |
|---|---|
| `NPF_DATA_DIR` | Базовая папка данных (подпапки ПУ/БУ внутри) |
| `NPF_PU_DIR` | Прямой путь к папке ПУ |
| `NPF_BU_DIR` | Прямой путь к папке БУ |

```bat
set NPF_PU_DIR=C:\Сверка БУ-ПУ\Приложение_1\ПУ
set NPF_BU_DIR=AI-1С:\Сверка БУ-ПУ\Приложение_1\БУ
python -m npf_recon
```

## 🔌 Переход на API (портируемость)

Бизнес-логика (агрегация, сверка, отчёт, экспорт) работает только с
нормализованными `Record` и **не знает** формата источника. Чтобы перейти с
файлов на API, достаточно реализовать новый `Source`:

```python
class ApiSource(Source):
    def scan(self) -> list[RawDocument]:
        ...   # обращение к API вместо чтения файлов
```

и подставить его в `pipeline.py`. Слои `aggregate / reconcile / report /
llm_export` и все тесты остаются без изменений.

```
Source → RawDocument → Parser → Record → Aggregate → Reconcile → Report
                                                              ↘ LLM-экспорт
```
